# RGBBox 迷你游戏支柱（game-soul-diagnosis 输出）

> 2026-10-10 · 从用户「没触发灵魂」反馈 + G1-G4 评审证据提炼

## 支柱（3+1 句，可证伪）

**支柱 1**: 玩家在打开任意游戏的 10 秒内，房间灯光与画面同步变化——游戏不只是屏幕上的事，是整个空间的体验。

**支柱 2**: 每次升级都让玩家看到弹幕形态的质变（八向/穿透/连锁），画面在 3 分钟内从「孤单射击」变成「满屏弹幕的艺术」。

**支柱 3**: 死亡后的结算屏告诉玩家「差多远就能进化/解锁」，让「再来一局」成为本能而非选择。

**反支柱**: 这 *不是* 独立游戏——不需要世界观/角色/剧情/多平台/商店发布。它是 RGB 灯效客户端的游戏化延伸。如果某个改进只在屏幕内有效、不涉及灯效/产品闭环，它不是最高优先。

## 嵌套循环映射

| 层 | 时间 | 当前状态 | 目标状态 | 断裂修复 |
|---|---|---|---|---|
| **微循环** | 30 秒 | 射击/移动无反馈差异 | 每次击杀→灯效脉冲+音效+粒子；受击→红灯警告 | LED 联动 + 打击感 |
| **中循环** | 5-15 分钟 | 升级=数值堆叠 | 升级=弹幕形态质变（八向/穿透/连锁） | 升级卡重设计 |
| **宏循环** | 跨局 | 元进度死端 | 死亡→「差 X 就进化」→重开→灯效成长感 | 进化披露 + 死亡钩子 |

## MDA 反向验证

```
目标 Aesthetics:
  「Sensation」——房间灯光与游戏画面同步的全感官体验
  「Fantasy」——从「被追着跑的弱者」进化到「满屏弹幕的神」

需要 Dynamics:
  → 灯效随游戏事件实时变化（不只是预览）
  → 弹幕密度/形态随升级质变
  → boss 出现时房间进入「红色警报」

需要 Mechanics:
  → LED 联动管线（游戏事件→灯效输出）
  → 升级系统从乘数改为形态解锁
  → boss 入场演出（倒计时+灯效+震动）
```

## 数值层诊断（第三层）

支柱和循环明确后，数值问题是次要的——死亡墙已在 R220 修好（bot 验证 0/16 死亡）。当前数值的真正问题是：
- **升级无质变感**（+15% 射速 ×5 次≠体验变化）
- **击退钉死**（12px 叠加→威胁感为零）
- **进化不可见**（4 条配方零 UI 披露）

这些问题在支柱/循环修复后才有意义——先修身份，再修数字。
