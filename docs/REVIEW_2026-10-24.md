## 0. 一页结论

### 两个事件的因果链

**事件 A：构建机 `dist:win` ENOENT**（根因 Likely，机制 Confirmed）
```
electron zip 缓存损坏/缺失（%LOCALAPPDATA%\electron\Cache）
  → app-builder unpack-electron 静默产出缺 electron.exe 的 win-unpacked
  → rename electron.exe→RGBBox.exe 报 ENOENT（ElectronFramework.js:51-54）
```
electron-builder 26.8.1 默认**不读** `node_modules/electron/dist`，而是解压共享缓存 zip；`node_modules` 里的 dist 缺失是**同一缓存/网络故障下的共症状**（electron npm 包 postinstall 也从该 zip 解压）。PRD R216.6 有本机同构先例（用 `-c.electronDist` 绕过）。全链路当前**零检查、零自愈、零入库知识**（lessons.md 无记录，知识只在私有 memory）。

**事件 B：视频工作站打开「视频工作站」报错**（两候选待一次 Console 截图裁决）
- **候选 1（R-1，字面缺口 Confirmed / 拦截行为 Likely）**：打包版 CSP `media-src 'self' blob:` 漏 `media:` scheme——打包版所有 `media://local` 视频/音频/胶片缩略图被 CSP 拒载，配合 R94 自动恢复 =「打开视图即报错 ⚠ 无法播放：文件格式无效或不受支持」。**仅打包版**（dev 不注入 CSP）。
- **候选 2（R-2，Likely）**：playlist 存绝对路径（dev/打包共享 `%APPDATA%\rgbbox\config\video-playlist.json`），该机文件不可达 → 404 →「⚠ 无法播放：文件读取失败」。**唯一同时解释 dev+打包双报错**的机制。
- 放大器：E-7/R-3 renderer 崩溃无退避 reload（crash-loop）；E-16 工作档 profile 不走 shape 校验。
- 裁决方法：那台机器 `yarn dev` → 复现 → DevTools Console 截图（文案「格式无效」→R-1；「读取失败」→R-2；Console 有 CSP violation →R-1 实锤）。
