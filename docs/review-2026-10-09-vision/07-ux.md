# 07 · 体感/手势功能 交互与体验（UX）评审报告

- **评审对象**：RGBBox 视觉体感全链路——①MiniGamesView 游戏内 👁 体感（R131/R132/R136/R137/R138）、②右下浮囊 VisionAssistant 全软件手势助手（R142-E4b/R143）、③AI 实验室「体感」体检台（R144/R149/R151/R153）。
- **用户判定**：「现在只能是一个玩具 demo 体验，要达到真正的商业用途」。历史：R136 用户曾否定整版（「体验极差…提示不及时不合理」），R143 再否定（助手/和弦文本「完全不能用」）。
- **评审框架**：Nielsen 十大启发式 + Fitts 定律 + 感知性能；受众 = 无技术背景的桌面灯效玩家/迷你游戏玩家。
- **方法与证据等级**：`[V]` = 亲自读到代码（file:line）或看到截图；`[I]` = 推断/Speculative。截图注意：docs 下截图多为对应 R-N 时点的静态基线，**只能证明 UI 存在，不能证明动态交互质量**；所有动态结论以现行代码逻辑为准，OCR 低置信处已与源码文案核对。
- **本评审未运行应用**（按约束不启动 electron），无真机手感数据；引用的延迟/帧率数字均出自 PRD 自检证据（合成源）。

## 1. 问题清单（按严重度排序）

严重度：P0=阻断首次成功/错误恢复；P1=显著伤害商业可用性；P2=明显打磨缺口；P3=细节。

### X-1【P0】摄像头失败 = 全静默 + 开关「变砖」+ 假错误文案
- **位置**：`src/renderer/src/components/MiniGamesView.tsx:2351`（`vision.enable().catch(() => undefined)`）；`src/renderer/src/components/AiLabVisionTab.tsx:394`（`catch { /* camera denied — the state chip tells the story */ }`——但该 chip 只会显示「未开启」）；根因在 `src/renderer/src/hooks/useVisionInput.ts:165,177-237` + `src/renderer/src/visionHostMain.js:152-155`。
- **现象**（代码级推演，[V]）：getUserMedia 抛错（权限拒绝/无摄像头/被占用/OS 隐私开关）→ 宿主只 post `{type:'error'}` → hook `reject` 但 **`channelRef.current` 已在 await 前赋值且无失败清理** → `enabled` 保持 false。三重后果：
  1. **静默**：两处调用方都吞掉异常，无任何弹窗/横幅/文案；AI 体检台的 chip 只显示「未开启」。
  2. **变砖**：再次点击开启 → `start()` 因 `if (channelRef.current) return`（useVisionInput.ts:165）直接早退，**永远无重试**，隐藏宿主窗也泄漏不关。唯一恢复 = 离开视图再回来（unmount → disable）。
  3. **假错误**：初始化期间 pipeline 先 post `onStatus('loading models…'/'models ready')`（pipeline.js:46,65）→ `setLabel` → 游戏状态条渲染 `· 👁 体感启动失败: models ready`（MiniGamesView.tsx:2125 在 `!enabled && label` 分支硬套 error 前缀）——正常加载期闪现、失败后**永久显示**语义矛盾的文案。
- **测试缺口**：`tests/renderer/hooks/useVisionInput.test.tsx:175` 用例名为 "rejects enable() and cleans up"，但断言只有 `enabled===false`，**未验证 channelRef/host 窗清理**——标题与断言不符，绿灯掩盖了变砖。
- **为什么伤体验**：无摄像头/权限被系统关掉是真实世界高发路径；此时用户点按钮「没反应」，商业产品里这是 1 星差评场景。Nielsen #9（错误恢复）直接不及格。
- **建议**：① `start()` 失败路径加 `.finally` 清理（channel close、`visionHostClose`、复位 refs）；② 错误按 `err.name` 分类（NotAllowedError→「摄像头权限被系统拒绝，请在 Windows 设置 > 隐私 > 相机开启」；NotFound→「未检测到摄像头」；NotReadable→「摄像头被其他应用占用」）驱动一个 **banner 错误态**（VisionBanner 加 `kind='error'`）；③ 初始化期的 status 文案不套「体感启动失败」前缀（区分 starting/error 两态，见 §4 蓝图）。
- **收益**：把最恶劣的失败路径从「假死」变成「一句话+一个动作」。
- **等级**：[V]（代码逻辑完整读证；真机表现待人工复核 #1）。

### X-2【P0】手势助手首次启用 = 「隐形校准向导」，无任何引导
- **位置**：`src/renderer/src/components/vision/VisionAssistant.tsx:116-181`——组件只渲染 pill / badge（`手势助手模式`）/ VisionCursor / 径向菜单 / 和弦教练；**没有 VisionBanner、没有 VisionPad**。全仓 `VisionBanner` 仅挂载于 MiniGamesView.tsx:2841。
- **现象**：[V] 首次（无持久化 profile）在仪表盘/任意非游戏视图点开助手 pill → 完整三步校准向导在后台运行——**屏幕上没有任何步骤提示、没有任何「请抬手」文案**。用户只看到 pill 变亮 + 顶部一条静态「手势助手模式」徽标 + （检测到手后）光标环开始漂移。校准失败的「重试/继续采样」文案同样无处显示。R133 的 profile 短路只帮老用户。
- **为什么伤体验**：三个入口里这是唯一「全局」入口；新用户最可能先点它（常驻右下角），然后遭遇 10-20 秒的黑箱期——「点了没反应」的玩具感即由此而来。
- **建议**：助手模式下挂同一个 `VisionBanner`（props 传 vision handle 即可，组件本就自包含）；首启用额外加一屏「摄像头将开启 · 3 个核心手势示意 · 开始」确认层（顺带解决隐私告知，见 §3-10）。
- **等级**：[V]（组件渲染面读证）。

### X-3【P0】首次可发现性：游戏库 hub 无任何文字体感入口
- **位置**：游戏 hub 工具栏只有一个 **纯图标 EyeOff** 按钮（MiniGamesView.tsx:1980-1985，且它是「手势指示器」开关而非体感开关）；带「体感」文字的开关只出现在**进入具体游戏后**的工具栏（MiniGamesView.tsx:2343-2352），混在 10 个按钮里。Slash 磁贴文案宣称「手势原生玩法」但 hub 无任何开启路径。
- **证据**：`docs/ui-baseline/games.png`（当前基线）——图像分析确认「没有任何带文字的体感/手势入口」，眼睛-斜杠图标被分析模型误读为「桌面待机可视化开关」；`docs/screenshots/r131-tetris-active.png` 显示游戏内工具栏确有「👁 体感 / ⇄ 镜像 / ⚡ 标准」。
- **为什么伤体验**：无技术背景用户走不到「看见 👁 开关」这一步——评审任务书假设的起点本身不成立。Nielsen #6（可发现性/信息架构）。
- **建议**：① hub 四游戏磁贴加「👁 体感可玩」角标（TD 标「鼠标」）；② 点角标直达教学卡（§3-6）+ 跳入对应游戏并预开体感；③ 光刃斩击磁贴的「手势原生玩法」做成可点链接。
- **等级**：[V]（截图+代码双证）。

### X-4【P0】引擎文案 i18n 双向漏：英文用户看中文、中文用户看英文
- **位置**：引擎内置文案直出三层 UI：
  - `src/renderer/src/vision/session.js:46-56,104,217-274,303,392,475-479`——`STATE_LABELS`（'已激活'/'未检测到手 — 抬手进入画面'…）、`CAL_STEPS` 提示、`继续采样 — …`、`重试 — …` 全部中文；
  - `src/renderer/src/vision/pipeline.js:16-20`——`PIPELINE_SENSITIVITY` label 中文；`pipeline.js:46,65`、`visionHostMain.js:59`、`vision_input.js:193`——`loading models…`/`models ready`/`GPU delegate unavailable…, CPU fallback`/`frame error:` 英文；
  - UI 侧 `VisionBanner.tsx:52` 与 `MiniGamesView.tsx:2124` 都以 `vision.label ||` **优先引擎文案**——**en 用户在横幅常态看到「已激活」「重试 — 伸展幅度太小…」**；zh 用户在启动/降级期看到英文 status。
- **实测锚点**：r131-tetris-active.png 横幅显示「● 已激活」（引擎文案），而 i18n 键 `games.vision.state.active` 的 zh 值是「体感已激活」——i18n 版本从未被用到（label 非空时）。
- **为什么伤体验**：R131.6 自认的债，三个 P0 级重构（R136/R142/R143）都没还；对英文用户这是「未本地化的小作坊」直感。
- **建议**：session.js 的 label/status 改为**稳定 code**（如 `state:active`、`cal:retry:center:jitter`），UI 层按 code 映射 zh/en；status 型英文（models ready 等）并入同一机制。工作量集中在一个映射表 + 三处消费点改判空。
- **等级**：[V]。

### X-5【P1】R134「宽容校准」的教练文案被三处 UI 全部丢弃
- **位置**：`session.js:206-215` `_gate` 的 `继续采样 — 手可见率仅 42%,请正对摄像头…`（带具体数字的 actionable 反馈，R134 专门为修「重试死循环」而做）——但：

### X-6【P1】VisionPad 默认隐藏 → R136「看得见的闭环」断裂；R207 声称的设置页入口不存在
- **位置**：`MiniGamesView.tsx:266-270`（`rgbbox:visionPadVisible` 默认 **false**）+ 2843 双条件挂载；`src/renderer/src/components/SettingsView.tsx` grep `vision|体感|手势` **0 命中**——而 PRD R207 验收点写明「设置页+游戏顶栏双入口」（PRD:3713-3715）。设置页入口**不存在**，只剩游戏顶栏一个 icon-only Eye 临时入口（MiniGamesView.tsx:2336 注释自称「设置页为主入口」）。

- **等级**：[V]。

### X-7【P1】状态机缺口：「没手」四态不分、searching 态零建议、「已激活」语义悬空
- **位置**：`VisionBanner.tsx:46-52`、`useVisionInput.ts:13`、`envCoach.ts:27-33`。
- **现象**：[V]
  1. **四种「没手」共用一条文案**：摄像头未开（idle，无横幅——mount 条件 `vision.enabled` 为 false 时横幅不存在）、未检测到手（searching）、active 丢手（`active && !handSeen`）、识别率低（无此状态）——前两者文案几乎相同（'未检测到手——请抬手进入画面'），第三者同文案换橙点。用户无法区分「我该抬手 / 我离太远 / 灯太暗 / 摄像头根本没开」。
  2. **searching 态无环境建议**：envCoach 的 `too-far`（手丢失→移近 50-80cm）只在 `state==='active'` 时计算（VisionBanner.tsx:35 `handLost: vision.state === 'active' && !vision.handSeen`）；dim-light/low-fps 建议虽全态可出现，但 darkest 场景（用户根本没意识到要抬手/距离）发生在 searching。
  3. **「已激活」歧义**：active+handSeen 常态横幅只写引擎 label「已激活」（X-4），不说明「什么」已激活；截图分析模型原话：「首次使用的用户无从得知这是体感状态」。
  4. **paused 歧义**：进入 TD（鼠标作）自动 `setPaused(true)`（MiniGamesView.tsx:1000-1010），横幅显示「已暂停」——用户不知道是自己做错了什么还是这游戏不支持。
- **建议**：按 §4 蓝图把状态机显式化为 9 怣并各配文案+视觉+建议行；searching>8s 升级建议（复用 envCoach，把 handLost 条件放宽到 searching）。
- **等级**：[V]（部分子项如「识别率低」无数据支撑，标 [I]）。

### X-8【P1】手势词汇在游戏内零教学：chord 命令被消费但无一处文档
- **位置**：`MiniGamesView.tsx:816-846` 消费 `chord:confirm`（轮盘确认/开局）、`chord:back`（返回游戏库）、`chord:select`（点击光标悬停元素）——但游戏 UI 内**没有任何和弦教学**：`games.vision.radialHint`/`chordTextHint`/`chordPosture` 只出现在 VisionAssistant；`AiLabVisionTab` 的 CAPS 目录（唯一完整词汇表）藏在 AI 实验室第 5 个 tab 里。开局提示只有「捏合——或张掌保持约 1 秒开局」（`games.vision.startHint`）。
- **为什么伤体验**：任务书待证伪的假设「普通用户不加教练就学不会手势词汇」——对 chord 类**成立**：一个 Survival 玩家永远不知道「食指+中指 = 确认」能用来确认升级轮盘（轮盘提示只写「方向切换 · 快速捏合 2 次确认」，`games.vision.rouletteHint`）。8 向/捏合/张掌靠隐喻可猜，和弦不可猜。
- **建议**：游戏画布角落实装「?」手势速查浮层（数据复用 AiLab CAPS 的 name/how 双语字面量，抽成共享模块）；升级轮盘 hint 补「或 食指+中指 确认」。
- **等级**：[V]。

### X-9【P1】误触发不可撤销：Tetris 捏合=硬降，sport 档 confirmMs=0
- **位置**：`MiniGamesView.tsx:918-928`（queue 'space' → Tetris hard drop，即时结算）；`useVisionInput.ts:39`（`sport: 0` 确认窗）。
- **现象**：[I]（机制 [V]，误触率未实测）检测抖动产生的假 pinch 在 sport 档零确认直接硬降——Tetris 里等于毁一局；无 undo、无「上一动作回退」。商用体感产品对**不可逆高代价动作**普遍加确认或冷却（本作自己的捏合引爆都有 6s 冷却，PRD R142-E4）。
- **建议**：hard drop 保留 confirm 窗下限（sport 档对 'space' 至少 30ms 或双捏合）；或「连续 2 次误触内自动升回 standard 并 toast 提示」。
- **等级**：机制 [V] / 风险量级 [I]。

### X-13【P2】疲劳与用眼管理缺失

### X-14【P2】图标语义冲突：两个相邻 Eye 按钮 + 纯图标校准钮
- **位置**：游戏工具栏顺序为 `[Eye/Off pad开关(纯图标)] → [👁 体感(带字)] → [⟲ 重新校准(纯图标)]`（MiniGamesView.tsx:2336-2358）——pad 开关与体感开关用**同一对 Eye/EyeOff 图标**；重新校准在体感开启前隐藏、开启后纯图标。r131 截图的图像分析把 ⟲ 判为「含义不明」。pad 开关在体感关闭时也可点（点了无效果——pad 本就只在 enabled 时挂载），无禁用态。
- **建议**：pad 开关换 Speedometer/Compass 类图标 + 体感关闭时 disabled；校准钮并入 ⇄ 长按菜单或给文字。
- **等级**：[V]。

### X-15【P3】VisionPad 文字 9-11px、截断、aria-hidden
- **位置**：`VisionPad.tsx:126-137`（`600 11px` 状态行、`10px` 两行统计）、`ellipsize` 至 148px（PAD_W-20）；实锤：r144-vision-lab.png 探索面板中 pad 状态行显示「手自然张开，停在画面中…」被截断。`aria-hidden="true"`（VisionPad.tsx:98）——pad 内容对读屏不可达（banner `role="status"` 部分兜底）。
- **等级**：[V]（截图+代码）。

### X-16【P3】对局中横幅常驻「已激活」= 纯噪声 + 遮挡游戏画面
- **位置**：`MiniGamesView.tsx:2841` 横幅随 `vision.enabled` 常驻画布顶部居中（`app.css:1987` top:10px, max-width 560px）；running 态内容永远是无信息量的「已激活」（见 X-4），却持续占据顶部视野——Slash 这类顶部出块的游戏被半透明条幅压住。pointer-events:none 不挡点击但挡视线。
- **建议**：active 稳定 3-5s 后淡出至 8px 状态点（点击/hover 展开）；状态变化（丢手/建议）再弹回。
- **等级**：[V]（遮挡程度 [I]，需真机确认对玩法影响）。

### X-17【P3】启动期状态语义混杂（顺带）
- pipeline 的英文 status（'loading models…'）会直接进 label 通道并被游戏 chip 当错误渲染（X-1.3 的一部分）；GPU 回退 status `'GPU delegate unavailable (…), CPU fallback'` 同理。体检台 `statsText` 初始可能显示 `0 fps`（AiLabVisionTab.tsx:418-421，`inferFps` 未更新时 Math.round(0)）。
- **等级**：[V]（代码）/ 表现 [I]。

## 4. 理想交互蓝图：商业级体感 UX 反馈系统规范（状态机 × 文案 × 视觉层）

**统一状态机（引擎与 UI 共享 code）**：

```
idle ──enable()──▶ starting ──ready──▶ searching ──hand──▶ calibrating{center|reach|pinch}
  ▲                  ││                   ▲                   │extend(宽限,保留样本)   
  │            error◀─┘│                   │no-hand(≥45帧)    │retry(同步重启)
 disable()             └─permission/denied─┘                   ▼
  ▲                                                            active ──handlost(5帧滞回)──▶ active.lost
  └──────────────────────── disable()/离开视图 ◀──────────────────────┘        (回 searching 语义应区分)
                                            active ⇄ paused (TD 屏/显式)
```

| 状态 | 视觉层（banner kind/dot） | zh 文案（示例） | 附加行 | 自动行为 |
|------|--------------------------|----------------|--------|---------|
| starting | 蓝点 + spinner | 正在启动体感 · 加载模型… | — | 失败→error，不显示假错误 |
| error.permission | 红点 | 摄像头权限被系统拒绝 | 「Windows 设置 > 隐私 > 相机 > 允许 RGBBox」+ 重试按钮 | 重试可用（清理后） |
| error.busy | 红点 | 摄像头被其他应用占用 | 「关闭正在使用相机的程序后重试」+ 重试 | 同上 |
| error.no-device | 红点 | 未检测到摄像头 | 检查连接 + 重试 | 同上 |
| searching | 灰点脉冲 | 请把手举到摄像头前（50-80cm） | >8s：距离/光线建议（envCoach 扩展） | pad+骨架自动显示 |
| calibrating.step | 琥珀点 + 步骤进度弧 | 校准 N/3 · 步骤 hint（i18n） | 姿势提示（肘部支撑）+ 跳过 | pad 显示 provisionalCenter |
| calibrating.extend | 琥珀点 | 继续采样 — {具体诊断数字} | 同上 | **进度弧不清零**（保留样本可视化） |
| calibrating.retry | 琥珀点闪 | 重试 — {原因} + 上次失败原因 | 「连续失败 2 次？跳过校准也能玩」 | 第 2 次失败起 skip 高亮 |
| active | 绿点 | 体感已激活 · 摄像头工作中 | 3s 后整条淡出为 8px 状态点 | pad 淡出（hover 唤回） |
| active.lost | 橙点 | 手丢失 — 移回画面 / 移近一点 | too-far 建议 | pad+骨架自动弹回 |
| paused | 灰点 | 体感已暂停（此游戏用鼠标） | 「返回蜂群/方块继续体感」 | TD 屏专用文案 |

**横幅布局规范**：`[状态点] [主文案] [次级提示] [操作按钮(跳过/重试)] [环境建议]`，超过 max-width 时**建议行先折行**、主文案不 ellipsize（对比现状 VisionBanner.tsx:2016 nowrap+ellipsis）。
**声音**：离散手势 tick、完成 confirm（已有，R141-A，保留）；新增：error 一声低鸣、calibrating 步进完成短上行音（感知进度）。
**隐私**：active 态常驻最小化「摄像头工作中」指示（横幅淡出后保留 8px 绿点呼吸）；首次启用展示一屏用途说明。
**文案术语表（统一用词）**：功能总称=「体感」；单动作=「手势」；全局模式=「手势助手」；避免「视觉输入」面向用户出现（仅代码键名）。

## 8. 被推翻的假设 / 已验证无问题

**被推翻的任务书假设：**
