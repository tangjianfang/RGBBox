## 0. 执行摘要（一段话回答核心问题）

**上轮"玩具 demo"判定的五大差距，四大已被 R227–R305 实质性修复**（价值链接通：灯效环 v2 已让 6 词词汇直控产品主场景；首用向导 13.8s 全流程 walkthrough 10/10；错误恢复/隐私声明/soak 门禁齐备）。**但商业化没有随之发生**：README 与产品页对体感**零提及**（grep 实证 0 命中）、funnel 数据只埋不显、宏系统停留在孤儿决策矩阵、真机质量报告未落地。结论：**技术侧已跨过商业门槛，产品侧（叙事、发现性、可配置性、证据外化）停在门前**。体感的正确商业定位是「**灯效驾驶的免提通道 + 展示型差异化卖点**」，不是"主力输入替代鼠标键盘"——用户假设（差异化演示能力 vs 日常主力输入）**大方向成立但需修正一处**：控灯词汇（挥手切效果/捏合调亮度）已具备日频价值密度，问题不在收益不足，而在**发现性与信任证据缺失**。下一步最高杠杆不是新检测能力，而是：①产品叙事可见化；②把 gestureActions 孤儿矩阵接上用户（宏编辑器）；③把 funnel/体检台数据外化为用户可见的"质量面板"。

## 2. 用户价值假设检验（目标用户 × 场景）

**假设原文**：体感当前是"差异化演示能力"而非"日常主力输入"——手势学习成本 vs 收益不成比例，商业上更适合定位为可选购的炫技模块 + 无障碍备选输入。

**检验结论：方向成立，两处需修正。**

1. **修正一：收益密度已经不对称为零。** R247 灯效环 v2 落地后，「挥手切效果（curatedKinds 精选队列）+ 捏合保持 600ms 后上下调亮度 + 张掌定格 + 双捏撤销」是一个**完整的日频控灯闭环**——这正是上轮评审判定的"第一性差距（手势控一切唯独不控灯）"，现已修复。灯效玩家的"换效果/调亮度"是日频动作，隔空 2 米操作（桌搭展示、直播中途不打断画面）有真实价值。**学习成本也已收敛**：6 词权威表 + 13.8 秒向导 + 每步可跳过，"成本收益不成比例"的论据只剩"用户不知道这些"——是发现性问题，不是设计问题。
2. **修正二：'炫技模块'的贬义定位会低配它。** 正确定位是三层：**日常层**（灯效环=免提控灯，低学习成本高 retained value）、**展示层**（游戏四作+光标=内容创作/晒机素材，差异化卖点）、**声誉层**（无障碍备选输入=长期品牌资产）。三层共用同一 6 词词汇，边际成本递减。
3. **假设证伪的部分**：'可选购物模块'的'可选购'字面若指付费墙——**不成立**：开源 + 本地优先 + 无遥测的商业模式下，体感是获客与口碑资产，不是收入单元；其"商业价值"应以「装机转化率/留存叙事/传播素材」计量。

**场景价值排序（目标用户：RGB 玩家/桌搭爱好者/直播主，中文为主）**：

| 场景 | 价值 | 现状缺口 |
|------|------|----------|
| 直播中隔空切灯效/调亮度（不打断画面、不出镜鼠标） | ★★★★★（直播主核心痛点：画面专注度） | 已可用（灯效环），但直播主不知道它存在（叙事零曝光） |
| 桌搭日常免提控灯（人离屏 2 米） | ★★★★ | 已可用；缺 per-scene 宏（不同 mood 一手势一套效果） |
| 内容创作（手势玩法视频/教学素材） | ★★★★（中文平台"隔空控灯"有传播基因） | 缺演示模式：无录制/回放/慢放教学素材生成路径 |
| 游戏陪玩（四作手势原生） | ★★★（获客门面，非留存主力） | 已可用（R249 审计在册）；维持即可 |
| 无障碍（手部障碍/RSI 替代输入） | ★★★（伦理+商店叙事价值） | 零投入零声明；最便宜的声誉资产未认领 |

### T5（=C6）per-app 灯效场景联动 —— P2

### 5.1 现状盘点（已核实）

| 项 | 现状 | 商业缺口判定 |
|----|------|--------------|
| 分发/版本 | GitHub 开源、0.3.88、dist:win/mac | 无商店渠道（Steam/Microsoft Store 均未上）；开源+无付费=无收入模型，商业化的第一决策是**渠道与定价模式**，不在体感功能内 |
| 隐私声明 | **PRIVACY.md 已备且质量高**（R236：本地推理/零上传/零落盘/关闭即停/landmark 不出内存五承诺） | ✅ 已达商业线；缺 UI 内嵌入口的发现性（设置页有文案入口，已核） |
| 用户协议/EULA | 未见（grep PRD/docs 未见 EULA 文件） | **缺**——若走商店/付费分发是硬前置；开源阶段可延后 |
| 无障碍声明 | 零 | **缺**且便宜（C12）：摄像头上肢输入的辅助定位声明是"Accessibility"叙事的免费入场券 |
| 性能最低配置标注 | PERF-LEDGER.md 有台账（R241）但面向开发者 | **缺用户面版本**：体感 60fps 推理的 CPU/GPU 门槛（GPU delegate/NoSIMD 降级链已有，缺"推荐配置"文案） |

| 支持渠道 | GitHub Issues | 开源阶段够用；商业阶段需分类模板（体感类报障必附深度体检报告——与 T3 联动） |

| 遥测 | 无（本地优先） | **保持无**；funnel 已证明"本地计数也能做质量闭环"（C3 把它显示出来即可） |

### 5.2 体感模块商业定位建议

1. **默认关 + 高发现性引导开（维持现状的开关语义，修发现性）**：默认开违反"显式模式防 Midas Touch"的既定正确设计（R140 定律）；但当前默认关+零叙事=没人开。解法=C1 的首启 hint 卡：**30 秒 wow 时刻**=「向导第 4 步张掌定格那一瞬，整个桌面灯效随手的起伏呼吸」——walkthrough 已验证该链路 13.8s 可达，hint 卡把它推到用户眼前。
2. **卖点叙事分级**：对外只讲三句话——①「挥手切灯效、捏合调亮度」（日常价值）；②「4 款手势原生迷你游戏」（展示价值）；③「画面永不离开你的电脑」（信任价值，接 PRIVACY 五承诺）。24 能力/和弦文本/表情全部不出现在门面（体检台=实验室口径）。
3. **无障碍作为长期声誉位**：不承诺医疗级，声明"上肢操作不便者的辅助输入通道"，配键盘可达性核查。这是竞品（LAMP/SignalRGB 等主流 RGB 商业软件均无摄像头条线）无法快速跟进的差异化叙事。
