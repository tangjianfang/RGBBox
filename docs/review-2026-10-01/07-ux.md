## ① 问题清单（按严重度）

### P1

**X-1 survival 跨 hub 往返残留 running 态，ready 信息架构被旁路**
- 位置/现象：`MiniGamesView.tsx:276`（`survivalRef = useRef(initialSurvivalState())` 组件级存活）+ `enterGame`（:1447-1454）仅 `setScreen(next)` 不重置局面；`startSurvivalRun`（:1675-1695）只在 lost/ready 时重建。证据截图：`docs/ui-review/r219/sv-ready-window.png` —— 文件名为 ready，实际画面是 **running 态**（LV1、♥7、画布内 HUD、1/3 引导条，无 ready 面板、无难度选择、无开局 CTA）。
- 为什么伤人体工程学：用户「回游戏库→再进蜂群」的心智模型是重新开始（R219 刚把 ready 面板做成唯一主 CTA），实际却落在进行中的局；想改难度/角色必须先找到「重开」（而运行中 header 的开始/重开按钮按 R219.7② 又是隐藏的，只有 fs 暂停浮层里有）。同时 onboarding 1/3 引导条与 running 并存，说明引导完成度与局状态未解耦。
- 建议：回 hub 时若 phase=running 给「后台结算或暂停保存」二选一；重进时显示「继续上局 / 新开一局」双 CTA；引导条随局结束强制结算。
- 预期收益：消除新交互模型（R219 ready 抽屉）被旧状态旁路的割裂感；开局路径可预期。
- 证据等级：[V] 代码 + 截图（截图为运行态这一事实本身即残留证据；但「截图拍摄意图为 ready」为推断 [I]，可能只是抓拍时机问题——已按约束将其从「ready 布局证据」中排除，ready 布局以代码为证）。

**X-2 后台失败的用户可见性：AudioAi 1075 次失败期间的反馈矛盾 + 无自愈入口**
- 位置/现象：日志 1075×`Load model file:///...silero_vad.onnx failed`（2026-09-13→09-14）；期间 UI 徽章仍报「模型就绪」（`AiLabAudioTab.tsx:58-60` 只查 `sileroCached/astCached` 存在性+尺寸）；renderer 侧 `useAiAudioStream.ts:63-71` 只在**连续 >10 次失败**后才把原始英文 ONNX 错误（`Load model from file:///...`）写进 error state，无「重新下载/校验」动作。root cause（file:// URL + 截断文件）已由 R90.9 修复：[V] `src/main/index.ts:1240-1263`（plain path + ±10% 字节校验自动删除坏档），失败止于 09-14，且现盘上 `silero_vad.onnx` 639,335 字节与 manifest 逐字节一致。
- 残余问题（仍可复现的模式）：①「就绪」徽章语义=文件在盘，≠能加载；②真实加载失败以原始技术文案迟到出现；③残余 433×`no active audio stream`（09-22、09-26 仍在发生，`rgbbox.log` 5872/6921-6924 行）属会话竞态，5 连发以下永远触发不了 error 态——**对该形态用户完全无感** [I]（触发阈值 >10）。
- 建议：模型徽章增加「自检通过」档位（起 3s tone 自检已有，`AiLabAudioTab.tsx:149+`，把结果并入徽章）；任何 pipeline 失败固定给出「重试/重新下载」按钮；`no active audio stream` 竞态在 main 侧排队而非报错。
- 证据等级：[V] 日志 + 代码；「433 次竞态用户无感」为 [I]（阈值推断）。

**X-3 定时关机一键即布防，无确认、无安全默认**
- 位置/现象：`ShutdownTimerPanel.tsx:108-136` —— 点击任一预设（5/15/30/45/60min）或「布防」按钮立即 `shutdownArm`；`src/main/index.ts:282` 直接执行 `shutdown /s /f /t`（`/f` 强杀前台程序）。无确认对话框、无二次点击。缓解项：同一面板有显眼「取消」+顶栏 chip 显示倒计时（`AppShell.tsx:80-88`）。用户日志中有 4 次 `shutdown /s failed` 记录，说明该功能真实在用。
- 为什么伤人体工程学：危险操作（Nielsen #5 预防错误）预期两步或可逆；60 分钟档误点后若不盯 chip，机器直接关。
- 建议：复用 `fx-applied-toast` 的 5s undo 模式（App.tsx:549-557 已验证该组件带撤销按钮）——arm 后弹「已计划 XX 分钟后关机 · 撤销」；或预设点击后进入「确认布防」高亮态。
- 证据等级：[V] 代码三处 + 日志。

**X-4 图层删除：~20px 小热区 + 无确认 + 无撤销**
- 位置/现象：`useLayerActions.ts:106` `deleteLayer` 直接删；工作区每行图层尾部 trash 图标（截图视觉估 ~20px [I]）。对比：AI agent 删除、游戏存档清空、截屏画廊清空都有 `window.confirm`（`AiLabAgentTab.tsx:411`、`SettingsView.tsx:155-157`、`VideoStudioView.tsx:1794`），唯独图层没有。
- 为什么伤人体工程学：图层承载调好的参数（不透明度/混合/自动化），是用户投入最高的资产；Fitts 上又是最小目标 + 贴近行点击区。
- 建议：行级 5s undo toast（同 X-3 模式）或二次确认；trash 热区扩到 ≥32×32。
- 证据等级：[V] 代码无确认；尺寸 [I]。

## ④ 理想交互蓝图（不越界：纯软件、单人桌面）

1. **命令面板（Ctrl+K）**：聚合 55 效果 / 10 视图 / 曲目 / 游戏 / 预设直达。现有零件齐备：`MODULE_VIEWS` 枚举、效果 preset 表、i18n 类型化词典——一个 fuzzy 索引 + 一个 overlay 即可，无需路由/store（符合 ADR-006）。

4. **撤销体系泛化**：`fx-applied-toast`（role=status + undo 按钮，App.tsx:549-557）已是正确范式，抽成通用 `<UndoToast/>` 供关机/图层/overlay 区域改动复用。
