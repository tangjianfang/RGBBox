## 1. 引言

### 1.1 目的

本文档规定 RGBBox 迷你游戏模块（Balloon TD Arena / Nova Swarm / Neon Blocks / 光刃斩击，下称"四作"）可玩性升级的完整需求，覆盖功能需求、非功能需求、交付计划、验收口径与需求追踪。本文档服务于：①需求评审与批准；②R-N 条款拆分；③实施与验收对照。

### 1.2 范围

**范围内**：四作的玩法深化、表现层（Juice）补强、平台通用能力（教练/暂停/难度/全屏沉浸/遥测）、短局与每日挑战、本地双人、局域网联机。

**范围外**（见 §6.2）：互联网联机、账号与云服务、外部美术/音频素材、跨游戏经济互通、新增第五款游戏。

### 1.3 术语与缩写

| 术语 | 定义 |

## 2. 产品概述

### 2.1 背景

游戏模块经 R97–R142 迭代已具备：hub 磁贴 + 全屏、四作纯函数引擎（tick/draw 分离、命令队列输入）、合成音效与 BGM、体感/键盘/手柄三输入源、Swarm 完整 meta 层（角色/稀有度/轮盘/神器/成就/局外商店）。

对现状的全面审计（取证明细见附录 A）归纳出五类核心差距：

| 编号 | 差距 | 影响 |
| --- | --- | --- |
| GAP-1 | 策略信息不可见（TD 无波次情报、无放置反馈；Swarm 无出生预警） | 决策靠试错，深度无法表达 |
| GAP-2 | 无质变时刻（Swarm 强化全为线性叠层；Tetris 缺 Hold/SRS/T-spin 现代基建） | mastery 上限低，无"值得讲的一局" |
| GAP-3 | 表现层反馈不足（无顿帧/刀光/危险警示；Slash 炸弹充能不可见） | 打击感与审美不达线 |
| GAP-4 | 休闲底座缺失（无暂停、无难度档、全屏仍含边框面板、手势指示器常显） | 体验中断与视觉噪音 |
| GAP-5 | 长线动机单薄（TD 12 波封顶、三作仅 best 一个数字、BGM 单曲循环） | 通关即流失 |

### 2.2 产品定位与设计原则

**定位**：桌面工具内嵌的"小而美"街机模块——零素材、纯合成、每局 5–10 分钟。

**设计原则**（全期约束）：
1. **零素材全合成**：音效/音乐/图形全部程序生成，不引入外部资源文件。
2. **纯函数引擎 + 画布即界面**：引擎 tick/draw 分离、输入走命令队列；React 只做壳，全屏态一切信息由画布绘制。
3. **每作一个记忆点**：TD=词缀波突破、Swarm=武器进化、Tetris=T-spin、Slash=连锁斩。
4. **威胁必预警**：一切可致失败的压力源在出现前应有可感知的预告。

### 2.3 用户画像与使用场景

| 画像 | 场景 | 本规格的响应 |
| --- | --- | --- |
| 休闲玩家（主流） | 工作间隙开一局，5–10 分钟，随时可能被叫走 | 短局矩阵（FR-G08）、全局暂停（FR-G05）、难度预设、首局引导（FR-G01） |
| 进阶玩家 | 追分、追构筑、追技巧表达 | Tetris 现代化（FR-TE01–05）、Swarm 进化（FR-SW01）、TD 无尽词缀（FR-TD02）、每日挑战（FR-G09） |
| 双人/聚会用户 | 同屏或局域网两台机器组局 | 本地双人（FR-MP01–04）、LAN 联机（FR-LN01–04） |
| 体感玩家 | 手势操作（Slash/Swarm/Tetris） | 手势指示器开关（FR-G04）、全屏画布化手势可视化（FR-G03） |

### 2.4 北极星指标

> **任何一局都能在 5–10 分钟内爽完，并让人想立刻再来一局。**

以三个本地遥测代理指标度量（依赖 FR-G02）：
- N1 重开间隔 p50 < 30s；
- N2 单局时长 p50 ∈ [4, 12] min；
- N3 "新高光"局占比 ≥ 20%（新高光 = NEW BEST / 首次 T-spin / 首次进化 / 词缀波突破，任一）。

## 4. 功能需求 — 平台通用层

需求描述中"应"为强制（shall），"宜"为建议（should）。每条验收标准即测试口径（单测 / E2E / 遥测 / 用户实测）。

### FR-G01 策略教练引擎（含首局引导） — P0 / M1 / R198

**描述**：
1. 每作引擎应导出纯函数 `hints(state): CoachHint[]`（字段：`text` / `tone: tip|warn|praise` / `priority`），由渲染层每 2–4s 评估一次；同一提示 30s 内不得重复。
2. 游戏屏应在画布下方提供"教练条"，轮播当前最高优先级提示；应提供一键关闭（`rgbbox:gamesCoach` 持久化），关闭后不再出现。
3. 首局引导：玩家首次进入每作时，教练条应转为 3 步顺序引导（示例——TD：放置首塔 → 开启波次 → 升级塔）；三步完成或玩家跳过后应永久退出，不再复现（按作持久化标记）。
4. 全屏态教练条应并入画布 HUD 绘制（依赖 FR-G03）。

**提示内容来源**（实现建议，可裁剪）：TD——金币闲置、漏怪归因、覆盖率联动（FR-TD01）；Swarm——敌人类型克制、进化前置提示（FR-SW01）、传送门拾取；Tetris——堆高治理、Hold 使用、连击维持；Slash——方向语义、连击夸奖。

**验收标准**：
- [ ] 每作 `hints()` ≥ 5 组单测（触发条件 + 30s 去重）
- [ ] 首局引导 E2E：进入 < 2s 出现第一步；三步后清除标记并复测不复现
- [ ] 教练条关闭开关持久化（E2E localStorage 断言）
- [ ] 教练条关闭率 < 30%（遥测）
- [ ] 用户真机验收："提示有用且不烦"

**依赖**：FR-G03（fs 态画布化）。

### FR-G02 本地遥测与 arcade profile — P0 / M1 / R198（随附交付）

**描述**：
1. 应建立本地遥测环形缓冲 `rgbbox:gamesRuns:<id>`：每作保留最近 20 局 `{date, score, duration, highlight}`；写入仅在单局结算时发生。
2. hub 应提供 arcade profile 展示：每作局数、累计时长、mastery 徽章（TD 三星/波数、Tetris 40 行 PB 与 T-spin 计数、Slash 勋章、Swarm 既有 meta）、每日连续天数（streak）。
3. 设置页应提供"一键清空游戏数据"（清空遥测与 profile 展示，不清最高分，除非用户在确认框中另行勾选）。
4. 遥测严禁任何网络行为。

**验收标准**：
- [ ] E2E：对局全程网络请求为空（network 钩子断言）
- [ ] 单测：ring buffer 滚动、profile 聚合与 buffer 一致
- [ ] E2E：清空入口生效且可撤销提示符合预期

**依赖**：无。

### FR-G03 全屏沉浸纯画布 — P0 / M1 / R206

**描述**：
1. 全屏（fs）态应隐藏全部 DOM 面板（顶栏/侧栏/状态条/教练条/轮盘浮层），画布等比放大至视口，垂直利用率 ≥ 95%（现状约 76%，取证见附录 A-F10）。
2. 应新建共享画布 HUD 模块 `games/hud.ts`：画布内按钮绘制、指针悬停/点击 hit-test、tooltip、面板底板；四作共用，统一字号与 accent 体系（消除既有两份重复 `drawOverlay`）。
3. 各游戏画布化内容：
   - TD：塔商店画布底部横排（快捷键 1–5），选中塔的升级/出售为画布按钮；波次情报与倒计时绘于路径留白区；
   - Swarm：升级三选一卡、死亡战报画布化（数字键 1/2/3 + 手势焦点环沿用）；局外商店/构筑栏在 fs 态不显示；
   - Tetris / Slash：ready/lost 覆盖层按钮具备点击热区与键盘等价操作。
4. fs 态应仅保留一个鼠标移动时短暂出现的退出角标（3s 无操作自动隐藏）。
5. Esc 语义应分层：fs 态内按 Esc 打开暂停浮层（FR-G05），不直接退出全屏；暂停浮层内提供"退出全屏"。
6. 手势可视化（VisionPad / VisionBanner / VisionCursor）在 fs 态应改为画布内绘制，数据源不变；不应存在 DOM 悬浮物。

**验收标准**：
- [ ] E2E：fs 态 DOM 面板数 = 0（除退出角标）
- [ ] E2E：画布垂直利用率 ≥ 95%
- [ ] E2E：画布按钮热区命中 10/10（TD 商店、Swarm 三选一、各覆盖层按钮）
- [ ] E2E：全部画布按钮均有键盘快捷键等价物（可达性）
- [ ] E2E：Esc 分层语义无冲突

**依赖**：无（FR-G01/G05 与其联动）。

### FR-G04 手势指示器全局开关 — P0 / M1 / R207

**描述**：
1. 设置页应新增"游戏 · 手势视觉指示器"开关，**默认关闭**，状态持久化 `rgbbox:visionPadVisible`。
2. 仅当开关开启且手势模式启用时，才渲染右下角 `.vision-pad`；关闭态下该 DOM 不得存在。
3. 功能性手势组件（状态横幅 VisionBanner、悬停光标 VisionCursor）不受本开关影响。
4. 游戏顶栏应提供临时呼出入口（使未找到设置的玩家可快速开启）。

**验收标准**：
- [ ] E2E：首启（无存储）状态下 `.vision-pad` 不存在
- [ ] E2E：设置页与顶栏双入口切换后刷新仍生效
- [ ] E2E：关闭态下 banner / cursor 功能正常

**依赖**：无。

### FR-G05 全局暂停与难度预设 — P1 / M2 / R204

**描述**：
1. 四作应支持 P / Esc 暂停：暂停时冻结全部引擎 tick（含计时与倒计时），显示覆盖层（继续 / 重开 / 返回 hub）；恢复前应有 3-2-1 倒计时。
2. 难度预设：ready 态应提供"休闲 / 标准"二档（Swarm 可含"挑战"档），选择持久化：
   - TD 休闲：初始 30 命 + 300 金币；
   - Swarm 休闲：导演仁慈系数上调、刷怪密度封顶；
   - Tetris：起始等级 1 / 5 / 10 自选 + 提速曲线放缓（联动 FR-TE05）；
   - Slash 休闲：初始 5 心（标准 3 心，联动 FR-SL01）。
3. 暂停期间输入应被吸收（不写入命令队列、不改 held keys）。

**验收标准**：
- [ ] 单测：暂停前后引擎快照等价（含 Tetris dropTimer、Slash timeLeft、TD 波次倒计时）
- [ ] E2E：3-2-1 倒计时出现且恢复后状态无损
- [ ] E2E：难度选择持久化
- [ ] 用户实测：休闲档首次通关率 ≥ 60%（TD 12 波守住 / Slash 60s 存活口径，小样本）

**依赖**：FR-G03（fs 态暂停浮层画布化）。

### FR-G06 Juice 补强与统一结算（run recap） — P0 / M1 / R200

**描述**：
1. **hit-stop 顿帧**：四作应在高光命中瞬间（Slash 金块与 CHAIN、Tetris 4 消与 T-spin、Swarm 进化与 boss 击杀、TD 整波清空）冻结画面 40–60ms；冻结期间 dt 不得累积（恢复后不得跳帧）。
2. **出生预警**：Swarm 敌人入场前 0.5s 应在画布边缘对应方位显示红色警示箭头（TD 词缀波开波横幅同理预告）。
3. **Slash 刀光轨迹**：最近 6–8 帧出刀方向点应连成渐隐光带（与动量粒子并存）。
4. **Tetris 反馈**：落锁白闪、消行横向光束、背景/网格色随等级渐进偏移。
5. **统一 run recap**：四作单局结束应呈现统一结算（画布内）：本局得分、较上局与历史 best 的增量（如 `+12%`）、一个高光数据（最高连击 / T-spin 次数 / 到达波数 / 存活时长）、一句教练回顾（复用 FR-G01 文案通道）。

**验收标准**：
- [ ] 单测：hit-stop 冻结期间 dt 不累积（tick 注入验证）
- [ ] 遥测：出生预警上线后 Swarm"贴脸死亡"占比下降 ≥ 50%（前后对比）
- [ ] E2E：run recap 四作一致呈现且数据正确（截图复核）
- [ ] 用户实测：主观确认"打击感明显提升"

**依赖**：FR-G02（增量对比数据源）。

### FR-G07 BGM 分曲 — P1（一期）/ P2（二期）/ R205

**描述**：
1. 一期：四作应各配置一组静态音乐预设（调式 + BPM + 音色层，TD 沉稳 / Swarm 急促 / Tetris 上行 / Slash 强拍），进入游戏即切换；沿用既有合成管线，零素材。
2. 二期：应引入张力参数（Swarm=血量与敌密度、Tetris=堆高、TD=波次进度、Slash=剩余时间），映射到播放速度与叠加打击层；低血量宜转小调。

**验收标准**：
- [ ] E2E：进入各作后音频参数与预设一致
- [ ] 用户实测：音频线程 CPU 增幅 < 1%
- [ ] 单测（二期）：张力参数 → 速度/音高层映射纯函数

**依赖**：无。

### FR-G08 短局模式矩阵 — P1 / M2 / 并入各作 R-N

**描述**：各作应在 ready 态提供短局模式入口（≤ 1 次选择进入）：
- TD "速攻"：6 波制，独立最高分档；
- Swarm "冲刺"：10 分钟限时制，到时结算快照，独立最高分档；
- Tetris "40 行"：计时冲 40 行，记录个人最佳（PB）。

**验收标准**：
- [ ] E2E：三作短局模式均可进入且正常结算
- [ ] E2E：短局成绩与标准局分档持久化、互不覆盖

**依赖**：FR-TE01–03（Tetris 40 行的体验基础）。

### FR-G09 每日挑战与任务点灯 — P2 / M3

**描述**：
1. 应新建可种子化 RNG（mulberry32），四作将 `Math.random` 替换为模块级 `rand()`；普通局种子取时钟，每日局种子取当日日期（`YYYYMMDD`）。
2. 每日挑战：进入 daily 局使用当日种子（同日序列一致），成绩单列 daily best；hub 展示连续参与天数（streak）。
3. 每日任务：hub 每日 3 条（示例：TD 建 3 座霜塔 / Tetris 单次 4 消 / Slash 连击 20），完成即点亮；奖励仅为 profile 勋章（装饰性），**不得**引入跨游戏货币。

**验收标准**：
- [ ] 单测：同种子同序列 100% 复现（跨进程重启对照）
- [ ] 单测：streak 跨日累计正确（时钟注入）
- [ ] E2E：daily 成绩分档独立

**依赖**：FR-G02。

### 5.3 Neon Blocks（Tetris）

#### FR-TE01 Hold 槽与 lock delay — P0 / M1 / R199

**描述**：

2. 应实现 lock delay：落底后 0.5s 才锁定；移动/旋转可重置延迟，单块重置上限 15 次（防无限拖延）。

**验收标准**：
- [ ] 单测：Hold 交换与单块一次限制
- [ ] 单测：lock delay 计时、重置与 15 次上限

#### FR-TE02 SRS 踢墙表 — P0 / M1 / R199

**描述**：应以标准 SRS（Super Rotation System）踢墙偏移表替换现有 ±1/±2 水平尝试（I 块独立表），使 T-spin 等中级技巧物理可行。

**验收标准**：
- [ ] 单测：SRS 全表用例（J/L/S/Z/T × 各方向；I 专项）≥ 12 例

#### FR-TE03 T-spin / B2B / 连击计分 — P0 / M1 / R199

**描述**：
1. 应实现 3-corner T-spin 判定（TSS / TSD / TST），计分采用 guideline 量级（TSD 1200 × 等级、TST 1600 × 等级）。
2. 应实现 Back-to-Back（连续高难消除 ×1.5）与连击加成（+50 × combo × 等级）。
3. 触发时应呈现画布浮字演出（"T-SPIN DOUBLE!" 等）并计入高光统计（FR-G02）。

**验收标准**：
- [ ] 单测：3-corner 判定 TSS/TSD/TST 各 ≥ 2 例（正反例）
- [ ] 单测：B2B / 连击计分
- [ ] E2E：合成输入打出一次 TSD 并见浮字

#### FR-TE04 放置提示模式 — P0 / M1 / R199

**描述**：
1. 应提供可开关的"放置提示"：对当前块枚举全部合法摆位（10 × 4 旋转），以启发式评分（洞数 / 高度 / 凹凸 / 消行数）标出最优落点（ghost 上加星标）。
2. 提示计算应为纯函数且每块至多计算一次（性能预算内）。

**验收标准**：
- [ ] 单测：启发式在构造局面下选点正确 ≥ 5 例
- [ ] 遥测：开启提示时新手前 5 局 40 行达成时间 -30%

#### FR-TE05 危险警示与提速曲线修正 — P1 / M2 / R199

**验收标准**：
- [ ] 单测：分段表单调且端点合理（Lv1 ≥ 0.8s，Lv20 ≤ 0.08s 地板）
- [ ] E2E：危险态视觉与音频触发

### 6.2 局域网联机（M4，RA2 式建房）

**网络边界（强制）**：仅本网段 UDP 广播 + TCP 直连；无公网、无 NAT 穿透、无账号；零新增 npm 依赖（Node 原生 `dgram` / `net`）。

#### FR-LN01 房间发现与加入 — P3 / R209

**描述**：
1. 主进程应提供建房能力：创建后以 UDP 广播 beacon（1s 间隔，载荷：房间名 / 游戏 / 版本 / 当前人数）。
2. 加入方打开"加入"面板应自动列出同网段房间，点击即加入；应保留手输 IP 直连兜底。
3. 版本不一致应拒绝加入并提示。

**验收标准**：
- [ ] E2E（双实例）：建房 → 加入 ≤ 3 次点击、≤ 10s
- [ ] 单测：版本不匹配拒绝

#### FR-LN02 会话与同步模型 — P3 / R209

**描述**：
1. 会话走 TCP 直连；房主权威：房主运行引擎 tick，客端仅发送输入指令（建塔 / 升级 / 技能 / 方向）。
2. 房主以 10–20Hz 广播状态快照（仅渲染必需字段，紧凑 JSON）；客端插值渲染。
3. 渲染层通过既有 `window.rgbbox` IPC 桥扩展一组事件接入，不直接触网。

**验收标准**：
- [ ] E2E（本机回环 + 真机双机）：指令 RTT p95 < 10ms、快照 15Hz 稳定
- [ ] E2E：依赖清单零新增、网络请求零外联

#### FR-LN03 断线恢复与一致性 — P3 / R209

**描述**：
1. 会话应维持 2s 心跳；超时判定断线——房主可继续对局（客端位转 AI/暂停），客端可尝试重连或转观战。
2. 快照 hash 对账：双方以共享种子 RNG（FR-G09）校验关键状态，检测到漂移即触发重同步。

**验收标准**：
- [ ] E2E：模拟拔线 2s 内检出、重连成功率 ≥ 90%
- [ ] 单测：注入漂移 0 漏报

#### FR-LN04 / FR-LN05 TD 合作与 Tetris 对战 — P3 / R209

**描述**：LAN 首发游戏为 TD 合作（指令最稀疏，验证链路最优）；Tetris 对战以事件同步（消行事件 → 垃圾行）次发。Swarm 合作（快照最重）暂不纳入。

**验收标准**：
- [ ] E2E：双机完成一局 TD 合作与一局 Tetris 对战，结算一致
