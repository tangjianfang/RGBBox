# 蜂群生存战「质感与可玩性」升级方案（R218 规划稿 · 待用户 review）

> 来源：2026-09-30 用户实机反馈（8 项）+ 现状代码盘点。本文档为**优化+扩展后的完整方案**，批准后按 PRD R218 实施。
> 范围：Survival（新星蜂群）为主体；手柄 Start 通用化为四作共用层。

---

## 一、现状盘点（代码事实）

| 维度 | 现状 | 差距 |
|---|---|---|
| 生命值 | `maxHp = 5 + 角色hpMod + 永久成长`，心数显示 | 无血条可视化、无难度挂钩（R204 难度二档只接了 TD/Slash） |
| 敌人 | 3 常规种（brute 20px 肉盾/sprinter 11px 快速/chaser 14px 追击）+ boss 34px + elite 词缀 | 行为向量少（追与快两类本质），层次感不足 |
| 实体尺寸 | 玩家 14px、敌 11-34px（900×520 逻辑分辨率下半径） | 弹幕/光环叠加时视觉拥挤 |
| HUD | 顶栏文字+HP 心行直接绘制在画面上 | 不透明底色块感、占用画面 |
| 背景 | scene.ts 六场景（渐变+2-3 层视差）R213 交付 | 战斗中层次与动态响应弱 |
| 手柄 Start | **仅分配给 P1 的手柄** buttons[9] 可开局（`pollGamepad` pi===0 分支） | PS5 柄分配给 P2+ 时无法启动；三作其它无 start 路由 |
| 多人 HUD | 4P HP 行纵排画面顶部 | 未按人数/屏宽自适应居中 |
| ready 态 | 选战机+人数+场景+难度(部分作)+短局词缀+输入配置+升级预选同屏 | 首屏选择项过多 |

## 二、设计方案（用户 8 项 → 优化为 A-H 模块）

### A. HUD 半透明友好层

- 所有战斗 HUD（血条/波次/等级 XP/金币/计时/复活珠提示）统一：**半透明底 rgba(底色 8%-14%) + 1px 语义描边 + 高对比前景**，贴画布边缘布局，不进入中央 60% 注意区。
- 进度类（XP/波次/boss 血条）胶囊化；低血量时血条脉冲 + 画布边缘红色 vignette 呼吸警示（强度可关，设置记忆）。
- 提示文案（升级说明/复活提示/操作引导）走统一 toast 胶囊（半透明、3s 自动消退）。
- **依据**：WCAG AA 对比度 ≥4.5:1 在 10% 底上仍达标（用现有 --text 语义阶保证）；HUD 边缘化=FPS 游戏惯例（不遮挡准星区/走位区）。

### B. 实体尺寸重校 + 宽容判定

- 整体缩小：玩家 14→11、chaser 14→11、sprinter 11→9、brute 20→15、boss 34→28；子弹/光环/拾取半径同步按 0.75-0.8 系数缩放。
- **命中判定 ≤ 视觉直径 80%**（商业 STB/roguelite 宽容判定惯例）：受击不冤、贴脸不判。
- **依据**：实体直径 ≤ 屏宽 2.5%（玩家 22px/900≈2.4%）；缩小后同屏密度感知下降，「拥挤感」主要来自弹幕×大实体叠加，双管齐下。

### C. 背景层次与战斗响应

- 六场景升为**三层景深**：远景星云渐变（现有）+ 中景视差（加密 1.5×+色彩层次）+ **近景战斗响应层**——击杀涟漪、低 HP 红晕、boss 登场暗场聚焦。
- 场景与玩法联动（可选扩展，默认仅视觉）：不引入影响平衡的机制，保持「不影响游戏体验」边界。
- **依据**：视差/动态反馈是「质感」的视觉杠杆（juice）；分层与密度控制成本可控（scene.ts 纯绘制模块零逻辑侵入）。

### D. 敌人角色矩阵扩展（层次感+策略性核心）

现有 3+1 → **8 种行为正交的敌人**（每种逼迫玩家改变一种决策—— Vampire Survivors 设计法）：

| 敌人 | 行为 | 玩家决策改变 | 解锁波次 |
|---|---|---|---|
| chaser 追击者（现有，缩） | 直线追击 | 基础走位 | 1 |
| sprinter 疾行者（现有） | 快速突进 | 转向预判 | 2 |
| brute 肉盾（现有，缩） | 慢速高 HP | 集火优先级 | 3 |
| **tank 堡垒**（新） | 极慢极高 HP、阻挡弹道 | 绕行 vs 硬拆取舍 | 4 |
| **swarm 虫群**（新） | 一窝 8-12 小单位同源刷出 | 清屏类升级价值↑ | 3 |
| **shooter 炮手**（新） | 远程风筝、保持距离开火 | 主动突进切后排 | 5 |
| **splitter 分裂体**（新） | 死亡分裂 2 小体 | 击杀时机/位置控制 | 6 |
| **healer 医疗者**（新） | 光环治疗附近敌 | 最高集火优先级目标 | 7 |
| boss（现有，扩） | 保留弹幕三阶段+新增 1 个形态 | —— | 岛际 |

- 词缀（elite）系统保留并适配新敌人；投放曲线按**威胁值加权**（威胁=HP×DPS/速度²归一化），director 自适应节奏继续生效。
- **依据**：行为正交（每敌人一个独特「迫使决策」）+ 威胁值加权投放 = 商业 roguelite 数值框架；避免「更多敌人=更难」的同质堆量。

### E. 生命值血条化 + 难度挂钩（科学数值）

- 心数制 → **连续血条**：分段渐变（绿→黄→红随比例）、低血脉冲、受击闪白+数字飘字；复活珠保留。
- **难度四档**（R204 二档扩展为四档、survival 接入）：

| 档位 | HP 基数 | 敌伤系数 | 敌速系数 | 预期容错* |
|---|---|---|---|---|
| 休闲 | 10 | 0.65 | 0.9 | ~16 次受击 |
| 标准 | 7 | 1.0 | 1.0 | ~10 次 |
| 困难 | 5 | 1.35 | 1.08 | ~6 次 |
| 无尽炼狱 | 3 | 1.6 | 1.15 | ~3 次（追求极限） |

- \***依据**：eHP（有效生命）= HP / (敌方单次期望伤害)；以「一局 10 分钟期望受击频率 1.2 次/分钟」反推——标准档 ≈10 次容错 = 商业 roguelite 主流「每分钟约 1 次失误空间」；困难及以上压缩容错但给分数倍率（1×/1.5×/2×/3×）保持激励相容。
- 角色 hpMod/永久成长与难度乘法叠加；无敌帧 2s 保留。

### F. 手柄 Start/Options 通用化（四作共用层，优先修）

- **任何已分配手柄**的 buttons[9]（Xbox Start / PS5 DualSense Options，standard mapping 一致）：
  - ready/lost/结算态 → 开局/重开（survival/td/tetris/slash 四作统一）
  - 运行态 → 暂停/恢复（接 R206 fs 暂停浮层，非 fs 也支持）
- 修复根因：现 `pollGamepad` 仅 `pi===0` 分支检测 Start；改为遍历全映射，任一柄按下即触发（边沿检测防连发）。
- PS5 柄无法启动的另一可能：非 standard mapping 布局差异——实施时对 `pad.mapping!=='standard'` 的柄做 buttons 兜底扫描（9 失效时试 16），并在 UI 显示各柄连接状态与键位提示。
- **验收**：PS5 DualSense 实机：单柄（任意分配位）Start 可开局/重开/暂停；双柄任一可用。

### G. 多人 HUD 自适应居中

- 角色基本信息（血条+等级+角色名+复活状态）按**存活人数自适应布局**：1P 左上纵卡；2P 左右对角；3P/4P 顶部网格分列；组整体按画布宽居中，实时刷新（现有 HP 行泛化）。
- 尺寸随画布 CSS 宽度缩放（≥1200px 放大 1.15×、≤800px 缩 0.85×），全屏态自动适配。
- **依据**：多人协作游戏 HUD 惯例（分属角落→归属感）+ 用户指定的「按屏幕大小居中」取折中：**组居中+成员分列**。

### H. ready 态信息架构精简

- 首屏只留 **5 项以内**：①大号「开局」主按钮（Fitts：大且居下）②战机选择 ③人数 ④难度 ⑤场景。全部一行胶囊式（点选循环）。
- 高级项折叠进「更多设置」抽屉：输入配置/头像/升级自动预选/短局词缀/BGM——抽屉展开记忆（localStorage）。
- 上次选择全部记忆（战机/难度/场景/人数），重进即恢复，一键开局。
- **依据**：Hick 定律（首屏选择 ≤5）+ 渐进披露（NN/g）+ 选择记忆降低重复成本；与 R160「三层漏斗」设计哲学一致。

## 三、扩展项（方案附带，默认全做，可否决）

1. **击杀 juice**：hit-stop（击杀大敌冻结 1-2 帧）、克制屏震（boss 死亡 0.2s）、伤害数字飘字（可关）——「有质感」的触觉层。
2. **低血量心跳音效**（sfx 通道已有，跟随 BGM 开关体系）。
3. **设置持久化**：H 项记忆 + juice/vignette 开关入设置。

## 四、边界（不做）

- 不改核心循环（波次/升级三选一/自适应 director 语义保留）；
- 不动 LAN 链路与四作其它三作数值（F 手柄层除外）；
- 不加新 npm 依赖；全部纯 canvas 程序绘制。

## 五、分期实施建议（批准后）

| 期 | 内容 | 理由 |
|---|---|---|
| S1 | F 手柄通用化 + H ready 精简 + E 血条/难度 | 用户卡点（PS5 启动）与可玩性骨架 |
| S2 | A HUD 半透明 + B 尺寸重校 + G 多人 HUD + juice | 视觉质感层 |
| S3 | D 敌人矩阵 + C 背景层次 | 内容层（数值平衡工作量最大，独立验证） |

每期独立验收：typecheck/域内单测/全量 0 失败 + ui:snapshot + CDP 截图视觉复核 + 帧率 ≥60 抽查；S3 增加数值模拟单测（威胁值曲线/投放密度回归）。
