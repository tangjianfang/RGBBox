## 1. 现状全量 Review：用户的三个痛点逐一定位

### 1.1 层级地图（当前「换一个灯效并调好」的完整路径）

```
入口 A（工作区左栏）                          入口 B（效果库 tab）
├─ ① 选图层（5 层列表）                       ├─ ① 切到效果库 tab
├─ ② 效果 chips ×14（全是科学/太空主题）       ├─ ② 在 7 个 tab 里找分类
├─ ③ 快速自定义 6 场景 chips                  ├─ ③ 滚动找卡 → 点击应用
├─ ④ 动感 4 选项 ─ 强度 4 选项                └─ ④ 回工作区调参…
├─ ⑤ 细节 4 选项 ─ 色彩 4 选项
├─ ⑥ 「全部效果」→ 跳效果库
└─ ⑦ 逐参滑杆区（▼ 首屏折叠之下才可见）

调参语言 ×3 套并存：
  · 49 个长尾参数键（speed/hueShift/…/hologramDepth/glitchAmount，meta 驱动逐参滑杆）
  · 4 语义维度（动感/强度/细节/色彩——quickDimensions.ts，本质是 49 参数的语义打包映射）
  · 6 场景 profile（专注/游戏/派对/观影/放松/入睡）
```

### 1.2 量化实锤

| # | 发现 | 证据 |
|---|---|---|
| P-1 | **55 效果 × 3 套并行分类法**：效果库 7 tabs（经典 7/自定义图片 2/进阶 14/科学可视化 20/3D 4/GPU 6/音频 2）、工作区 14 chips、6 场景 profile——同一件事三条路径、三套词汇 | EffectsView tabs + `QUICK_EFFECT_KINDS` + quick-profile-row |
| P-2 | **工作区 quick chips 全是科学/太空主题**（aurora/black-hole/solar-system/dna-helix…），最常用的经典 7 效果（彩虹/呼吸/波浪）一个都不在——**默认 profile 自己的 5 个图层效果（aurora/fire/neon-pulse/starlight/nebula）也只有 2 个可达** | `quickDimensions.ts:15` + defaultProfile layers |
| P-3 | **49 个互不相同的调参键**横跨 55 效果（speed×48、hueShift×35、intensity×28、density×26 为公共面，另有 40+ 长尾：curtainHeight/glitchAmount/hologramDepth/pulseAmplitude…），逐参滑杆全部在 **1440×900 首屏折叠之下** | defaultProfile defaults 统计 + WorkspaceView 滑杆区行号 700+ |
| P-4 | **三套调参语言并存**：4 语义维度其实已经把 49 参数语义化打包（方向正确！），但它只是左栏中部一个普通小节，与逐参滑杆、场景 profile 互相无层级关系 | `applyQuickDimensionParameters` 映射表 |
| P-5 | **应用前无即时预览**：效果库卡片是静态相位缩略图，hover 不会在画布上试看；点了才知道长什么样 | EffectsView 卡片实现 |
| P-6 | 达成路径：换+调一个心仪灯效 ≈ **6-10 次点击/滚动**（选层→找入口→翻分类→应用→调 4 维→找不到的参数再翻折叠区） | 路径复算 |

**结论**：痛点的根源不是「效果太多」——55 个效果是玩家受众的资产；根源是**没有分层收纳**（全部平铺给用户选）和**没有唯一主路径**（三套分类法互相竞争）。`quickDimensions` 证明团队已经找到了正确方向（语义维度打包），但它被埋没成了左栏的一个小节。

## 2. 商业软件标杆解构

| 产品 | 模式 | 可借鉴 |
|---|---|---|
| **Philips Hue**（2025） | 策展式**场景库**（按时刻命名：阅读/放松/聚会）+ 一键激活 + 「动态场景」把静态场景一键变动画；实验性效果收进 Hue Labs | 场景是第一公民；效果是场景的可选修饰；实验性内容有明确的「进阶」归宿 |
| **LIFX** | 效果 = 4-6 个**瓦片**（色彩循环/律动/烛光/音乐），点开单个 sheet 只暴露 3-4 个滑杆 | 每个效果的调参面收敛到 ≤4 个有感知的控件 |
| **SignalRGB** | 效果浏览网格（live 缩略图）+ 选中后右侧固定参数轨 | 识别优于回忆：缩略图必须是 live 的 |
| **iCUE / Razer Synapse** | 图层+效果类型+全参数面板 | **反例**——正是 RGBBox 现在的路；玩家爱用但大众劝退 |
| **Govee** | 海量场景列表 + DIY 深编辑器分家 | 浅用/深玩分流，互不打扰 |

**四条人性化法则**（本方案的设计公理）：
1. **首屏选择 ≤12**（Hick 定律：选择集越大，决策时间对数增长——55 平铺是硬伤）；
2. **渐进披露**（NN/g：默认简单，进阶按需展开，而不是把全部复杂度先摊开）；
3. **识别优于回忆**（live 缩略图/hover 预览，让眼睛选而不是让记忆选）；
4. **搜索替代浏览**（长尾内容靠搜索+标签，不靠人肉翻 tab）。

## 3. 方案：「场景 → 精选 → 深调」三层漏斗

### 3.0 设计哲学

沿用 R148.2「舞台与观众席」：灯效是主角，选择器是节目单。节目单的职责是**三分钟内让观众选中演出**，而不是把全部剧目一次性念完。RGBBox 的双层受众都要伺候：**速用者**（1 步出效果）与**玩家**（49 参数都在，但收进抽屉）。

### 3.1 L1 场景层——「0 步理解」（升级现有 6 场景）

- 现有 6 个快速自定义 profile（专注/游戏/派对/观影/放松/入睡）**升级为首屏场景卡**：卡 = 名称 + live 缩略 canvas（复用效果卡缩略管线）+ 一键应用 + 激活态高亮。
- 场景卡置于工作区效果区顶部视觉主体位（现状位置不变，规格升级）；末尾一张「+ 保存当前为场景」卡。
- **不需要理解「效果/图层/参数」任何概念，1 次点击出完整灯效**。

### 3.2 L2 精选层——「1 步到达」（新增精选 + 改造全库入口）

- **「精选」12 卡常驻**（数据驱动生成，不手工维护）：默认 profile 在用效果（aurora/fire/neon-pulse/starlight/nebula）+ 经典 5（彩虹/呼吸/波浪/渐变/屏幕环境光）+ 收藏 top + 最近使用 top——规则化挑选，覆盖 80% 需求。
- **hover 即时预览**：悬停卡片 300ms 内画布切预览态；顶部出现胶囊「预览中——点击应用 · Esc 还原」；移开/Esc 无痕还原。**先看后定，点卡才提交**（识别优于回忆的落地）。
- **最近使用**（自动 5 个）+ **收藏**（现有功能）并入精选区右侧，不再散落。
- **55 个全量收进「全部效果」抽屉**：7 个 tabs 取消，替换为 **搜索框 + 标签筛选**（场景 tag × 动感快慢 × 色彩复杂度——三套旧分类法合并为一套由数据推导的标签，P-1 的三条路径收敛为一条）。抽屉内卡片规格不变。

### 3.3 L3 深调层——渐进披露（参数区三段式重排）

选中效果后，参数区从「折叠之下的滑杆平铺」重排为三段：

```
┌─ 语义微调（保留，即现有 4 维度）──────────┐
│ 动感 慢速|流动|活跃|冲击   强度 柔和|均衡|鲜明|拉满 │
│ 细节 简约|均衡|丰富|密集   色彩 冷调|暖调|霓虹|黑白 │
├─ 此效果主参数（≤3 个，首屏可见）───────────┤
│ 例：彩虹→宽度/角度   烛光→闪烁强度   星云→云团密度   │
│ （从 param meta 挑感知最强者；每个效果只露 ≤3）      │
├─ ▸ 高级（默认折叠）──────────────────────┤
│ 全部长尾参数滑杆 + 「恢复此效果默认」一键复位          │
└──────────────────────────────────────┘
```

- **主参数 ≤3** 解决 P-3：49 个长尾参数不删一个，但默认只让「对这个效果观感最有感知」的 ≤3 个上首屏（参数区同时上移到效果 chips 正下方，解决 P-3 的折叠之下问题）。
- 「高级」抽屉 = 玩家通道，加「恢复此效果默认」（一键回到 preset defaults，消除「调乱了不知道怎么回去」）。
- 4 语义维度升为参数区首段并更名「语义微调」，明示它与主参数/高级的从属关系（三套调参语言收敛为一棵树，P-4 关闭）。

### 3.4 横切交互细则

- **可撤销**：应用效果后 toast「已应用 波浪 — 撤销」（5s 窗口），防误点焦虑。
- **随机灵感**：精选区一枚「🎲 灵感」按钮 = 随机效果+随机色彩维度，hover 同样即时预览（把 55 个长尾变成探索乐趣而不是浏览负担）。
- **图层联动不变**：所有选择仍作用于当前选中图层（心智模型不变，只改呈现层）。

### 3.5 达成路径对账（方案 vs 现状）

| 任务 | 现状 | 方案后 |
|---|---|---|
| 今晚想看个灯效 | 翻 tab/滚卡片 ≈4-6 步 | 场景卡 **1 步** |
| 换个常用效果 | 左栏 chips 没有 → 进库找 ≈5-7 步 | 精选/最近 **2 步** |
| 找特定科学效果 | 记住它在哪个 tab ≈3-5 步 | 搜索「黑洞」**1-2 步** |
| 精调某效果观感 | 翻折叠区找滑杆 ≈4-6 步 | 主参数首屏 **1-2 步**（长尾 3 步） |

## 5. 边界与关系

- **不删任何效果**、不改 engine 参数语义与 layer parameters 持久化结构（全部改动在呈现层/信息架构层，旧 profile 完全兼容）；
- 与 R148 S3（逐 view 精修）、R156-S5（UI 打磨）正交——本方案若立项，workspace/effects 两 view 的 S3 精修合并进本方案批次执行，避免同屏两次大改；
- 分类标签由现有 preset 数据推导（kind 分组 + 参数画像），不新增手工维护面。
