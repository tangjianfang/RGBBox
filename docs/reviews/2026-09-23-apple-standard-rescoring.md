# 苹果软件开发标准重评分——R148 内部标准 vs Apple 标尺对照

**日期**:2026-09-23　**输入**:R155 测试报告 + R156 评分（内部 91/100）+ 本轮补采证据　**性质**:只读研究（R157 规划条款），`src/` 0 diff
**产出**:①现有标准澄清；②Apple 标尺定义（锚点全部来自 Apple 公开材料）；③十维重评分；④差值归因；⑤修订路线

---

## 1. 先回答：「顶级商业软件评分标准」现在是什么？

本项目目前用的是 **R148.1 自定义标准**（2026-09-21 定标，参照 Linear/Raycast/Fluent 解构，见 [`ui-research-notes`](./2026-09-21-ui-research-notes.md)）：

> 九维加权：**色彩 15 / 排印 15 / 组件态 15 / 间距布局 12 / 交互反馈 10 / 可访问性 10 / 动效 8 / 平台原生感 8 / 治理一致性 7**；每维基线入档、S 阶段各带目标分，全路线兑现 = 98/100（诚实分 95）。基线实测 **5.5/10**。

它是一把「设计系统符合度」标尺——衡量 UI 是否收敛到自家 token/组件/排印体系。R155/R156 的评分则是「测试结果健康度」标尺（门禁通过率/覆盖/体积/运行时）。两把尺都**没有**把苹果标准里最硬的几件事当必答题：运行时性能遥测（hang/首帧）、Dynamic Type 式文字缩放、屏幕阅读器面、暗亮双主题、崩溃率可见性。

**可以按苹果标准重评吗？可以。** 苹果没有发布过「百分制评分表」，但它的标准由四类公开材料构成，完全可以操作化为一把标尺：
1. **Human Interface Guidelines（HIG）**——设计哲学（清晰/克制/层次）、暗亮双主题、Dynamic Type、4.5:1 对比度、Reduced Motion；
2. **App Review Guidelines §2/§4**——崩溃/挂起即拒（2.1）、设计完备性（4.x「polished and refined」）；
3. **WWDC 性能预算**——**首帧 ≤400ms**（WWDC2019：400ms = 系统开屏动画时长，超了用户就感知慢）；**主线程无响应 >250ms 记一次 hang**（MetricKit `MXHangDiagnostic` 口径）；**动画 60fps**（ProMotion 120）；
4. **苹果质量文化**——空态/错误态完备、本地化 100%、「it just works」。

（锚点来源：[Apple「Analyzing responsiveness issues in your shipping app」WWDC2023](https://developer.apple.com/videos/play/wwdc2023/10246/)、[SwiftLee: App Launch Time](https://www.avanderlee.com/blog/app-launch-time-tips-performance/)、[New Relic: app launch times overview](https://docs.newrelic.com/docs/mobile-monitoring/mobile-app-monitoring/ui-monitoring/overview-app-launch-times/)）

## 3. 差值归因：91 → 81，那 10 分扣在哪？

| 缺口 | 内部标尺下 | 苹果标尺下 | 差值主因 |
|---|---|---|---|
| **可及性** | 计 10% 权重、以「体系存在」计分 | Dynamic Type 必达 + 阅读器面 + 对比度实测——三项里两项半不达标 | **最大单项**：0 rem 纯 px 排版在苹果口径是一票重扣 |
| **运行时遥测** | 探针空闲数据优秀即得高分 | hang 率/首帧/崩溃率**没有遥测 = 不知道 = 不过** | 完整冷启动、hang、60fps、crash-free 四个数全是空白 |
| **主题** | R148 S5 本就未做，内部尺不重罚 | 暗亮双主题是 HIG 基本功 | 0 处 `prefers-color-scheme` |
| **内容本地化** | 键位满对齐已算优 | 用户看得见的英文直出就是缺陷 | `defaultProfile.ts` 等数据字面量 |
| 反向：**隐私/平台集成/空态** | — | 苹果口径下 RGBBox 反而**加分**（local-first 零遥测、密钥加密、OS 级整合厚度） | 部分回血 |

**一句话结论**：苹果标准考的不是「门禁绿不绿」，而是「**用户可感知质量有没有数字证明、所有人能不能用**」——这两块恰是当前体系的盲区。

## 4. 苹果标准下的修订路线（R156 S1-S6 之上新增 A 批）

| 批 | 内容 | 苹果锚点 | 量级 | 风险 |
|---|---|---|---|---|
| **A1 性能遥测补全** | 完整冷启动（spawn→首帧）测量；主线程 hang 计数（>250ms 阈值，探针拦截 long task）；UI 动画 fps 采样——三者挂进 R156-S4 探针资产化 | 400ms / 250ms / 60fps | 1-2 天 | L1 |
| **A2 文本缩放（Dynamic Type 等价）** | px→rem 排印改造（308 处字号）+ 设置页字号档位（缩放 85%-150% 全布局不破） | Dynamic Type | **大工程 1-2 周** | **L2** |
| **A3 屏幕阅读器面** | aria/role 补齐走查（rail/磁贴/滑杆/transport/磁贴卡），导航可达性全检 | VoiceOver 等价 | 3-5 天 | L2 |
| **A4 对比度激活+修复** | = R156-S6 前半：token 配对表驱动审计 → 违例修复（含 architecture 快捷键提示） | 4.5:1 | 1-2 天 | L1 |
| **A5 内容级翻译** | `defaultProfile.ts` 效果描述 + 3D 面板 + 游戏命名 + AI5 状态串（R150.6 预留的合并 R-N，条款已在） | 本地化 100% | 2-3 天 | L1 |
| **A6 亮色主题** | = R148-S5（已规划，含 Mica 近似/系统 accent） | 暗亮双自适应 | 已有方案 | L2 |

**合并推演**：S1-S6（R156，综合 91→99 内部口径）+ A1/A4/A5（轻量三件，~1 周）→ 苹果口径约 **86-88**；再上 A2/A3/A6（重型三件，3-4 周）→ 苹果口径 **93-95**；到苹果口径 98 需 S5 原生质感全兑现——与 R148「诚实分 95、98 需 S5 全兑现」的判断**完全一致**。

## 5. 结论（对用户两问的直接回答）

1. **现有标准** = R148.1 自定义九维设计标尺（基线 5.5/10，目标 98，诚实分 95）+ R155/R156 的测试健康度标尺（91/100）——都是项目内部尺。
2. **可以按苹果标准重评，已重评**：十维苹果标尺（锚点全部来自 HIG/App Review/WWDC 公开材料）下 RGBBox = **81/100**。四个主要失分点是可及性（62）、运行时遥测空白、暗色单主题、内容本地化——它们在内部尺下不可见，在苹果尺下是硬缺口；而 local-first 隐私与平台集成在苹果尺下反而得分高于内部尺。修订路线 A1-A6 已并入 §4，全部待批准后立项。

## 6. 重评分 v2（2026-09-23 用户反馈修订版，当前权威口径）

> 用户反馈：①「当前的评分太高」；②「先不考虑暗亮双主题自适应，成本高」；③「目前 AI 自动化测试无法一次性全覆盖」。
> v2 口径三条修订：
> **(a) 主题项剔除**——暗亮双主题从标尺中移除（不计分、不扣分，设计维度只评其余 HIG 项）；
> **(b) 「已验证才记分」原则**——v1 给「未测项」按乐观假设给了分（如以页内 reload 365ms proxy 记启动分、以单点 heap 快照记内存分）；v2 未测一律按保守值计；
> **(c) 自动化边界显性化**——「AI 自动化测试无法一次性全覆盖」本身入档：每个维度标注「已验证 / 可自动化但未做 / 超出自动化边界」三类证据状态，让 72 分的构成可解释、可提升路径可计算。

### 6.2 v2 加权综合：**72.0/100**（v1：80.85 ≈ 81；内部标尺：91）

```
60×0.20 + 70×0.10 + 72×0.15 + 60×0.10 + 80×0.05
+ 75×0.15 + 85×0.10 + 85×0.05 + 82×0.05 + 82×0.05 = 72.0
```

### 6.3 分数的三段结构（为什么 72 是诚实的）

| 段 | 分数段 | 含义 |
|---|---|---|
| **已验证分** | **72（今天）** | 只算当前有实测证据的部分；三处空白锚点（冷启动/hang/fps）与遥测缺失全部按保守值计 |
| **自动化可达分** | **~80-82** | 把「可自动化但未做」补齐即可到：完整冷启动+hang+fps 采样（A1，1-2 天）、对比度激活修复（A4，1-2 天）、30min 泄漏采样（S4）——全部 AI 自动化可执行，无需人工 |
| **自动化边界外** | 93-95 | 需重型人工/设计投入：rem 化文字缩放（A2）、屏幕阅读器真人走查（A3）、原生质感（S5）——这正是「AI 自动化无法一次性全覆盖」的部分，对应分数差 ~13 分 |

### 6.4 结论

v1 的 81 分确实偏高：它把「没测出问题」当成了「没有问题」。v2 的 **72 分**是「当前证据能证明的水平」——其中约 **10 分是 AI 自动化下一到两周内就能拿回来的**（A1+A4+S4 探针补测），再往上属于自动化边界外的设计/可及性重投入（A2/A3/S5）。主题项已按用户指令移出标尺；「AI 全覆盖不可一蹴而就」已作为口径固化在 §6.1 证据状态列。
