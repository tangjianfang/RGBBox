## 0. 一页结论

### 因果链：为什么现在是「玩具 demo」

**引擎内核是产品级的，价值链和失败路径是 demo 级的。**

```
灯效应用的手势助手控一切、唯独不控灯（价值链断裂，08 实锤）
        ↓ 用户拿它没有非用不可的理由
任何一次异常 = 永久静默死（03/04 实锤：未导入的 handOpenness + tick 无守卫）
        ↓ 好不容易跑起来，一次小异常就悄悄全灭
失败路径全静默 + 零引导 + 双语泄漏（07 实锤：错误被吞、隐形校准、中英直出）
        ↓ 普通用户第一次就用不明白
真机零证据 + 宣称不可自证（02/06 实锤：60fps 无法自证、表情修饰键从未工作）
        ↓ 两次「体验极差」都发生在门禁全绿之后——自动化全绿 ≠ 用户可用
```

而好消息同样硬：**数据面干净（帧/landmark 全内存、零外发零落盘）、注入边界承诺成立（grep 零命中）、单帧推理 0.222ms 非瓶颈、BroadcastChannel 155µs@60Hz 余量足**——架构骨架（R136 推倒重设计的宿主进程方案）是对的，不需要再推倒，需要的是把 8 轮迭代攒下的「能力目录」收敛成「用户任务」。

## 2. 延迟与性能（02）

**结论：连续量已近商业线，离散指令差 2-3 倍。** 挥手方向键端到端估 ~195-230ms（目标 ≤80-100ms）、捏合 ~165-195ms、和弦 ~265-295ms；光标/模拟轴 ~50-90ms（预测渲染+60Hz 积分真实存在且全路径生效）。

- 根因一（Confirmed）：算法层确认延迟——默认 standard 档 `confirmMs=90`（`gesture_engine.js:88`）+ OneEuro 静止起步 67ms，node 实测方向阶跃 167ms@30Hz；**抬键（释放）也吃 confirm（133ms）**；sport 档 50-67ms 但非默认。
- 根因二（Confirmed）：遥测断链——采集统计算了没人读，「要 60 给 30」用户不可见，「60fps 采集」宣称无法自证（合成 E2E 实际 30Hz）。
- 根因三（Confirmed）：助理路径每 3 帧白付 face 推理 +34.6ms GPU，零消费。
- 次级：每帧 5×LatencyMeter.stats() 排序 300 样本 ~0.46ms/帧、cursor 每帧 elementFromPoint、和弦文本 30Hz 下限 ~4.3wpm（宣称 12）。
- **被推翻**：推理排队堆积（rVFC 处理完才重注册，天然丢帧保新——设计正确）；跨窗传视频帧（实际只传 ~2-3KB landmarks，892µs 传帧才是反模式）；4Hz 节流致状态滞后。
- 引擎量化（03）：框架单帧 p50 0.222ms / p95 0.458ms；snapshot 6.47KB；BroadcastChannel 155µs/条@60Hz。

## 3. 稳定性与生命周期（04 + 03）

**「happy path 全有测试，unhappy path 静默死或永久死」**——两次用户否定都发生在门禁全绿之后，此为结构性原因之一。

- 崩溃级（P0）：零 ErrorBoundary（任何视觉组件渲染异常=整窗白屏）；`handOpenness` 未导入；宿主 tick 无 try/catch（R136 迁移时丢失了旧主线程版的防御）；init 无超时可永久挂起。
- 死锁级（P0）：单宿主无所有权——助手+体检台并发时第二个 enable 永挂、先离开者 stop 连坐后者；enable 竞态双 channel 注入；失败后 channelRef 不回滚=按钮永久变砖。
- 泄漏级（P1）：`window-all-closed` 清理列表漏 visionHost（孤儿进程结构缺陷）；cursor NaN 永久污染无自愈；renderer 无全局 JS 错误捕获（与 Crashpad 空互证——不是没出错，是出了也看不见）。
- 设备级（P0/P1）：无 onended/devicechange/看门狗/deviceId 选择——拔线或被 Zoom 抢占=静默冻结、heldRef 卡键、UI 假活；pause 仍 60Hz 推理（R133 优化迁移回归）；校准中人走开无限滞留（fuzz 149/300 帧滞留）。
- 证伪：连点不会开两个宿主窗（main 单例守卫成立）；模型资产未被打包排除（out/ 实测存在）；crashReporter 已覆盖宿主进程（缺口在 renderer JS 层）。
